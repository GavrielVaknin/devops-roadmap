# 2026-08-20 — Volumes, scripting the VM lifecycle, and restructuring into a role

## Objective for this session
Finish container storage, stop rebuilding VMs by hand, and make the Ansible work look like something I would find in a real codebase.

## What I did
- Demonstrated named volumes and bind mounts, completing the set of four storage behaviours.
- Tore the whole virtualisation stack back off the machine — packages included — to see whether I could rebuild it from nothing. Then decided part-way through that memorising the sequence was the wrong goal and scripted it instead.
- Wrote `newvm.sh`, `rmvm.sh`, and `geninventory.sh`.
- Restructured the flat playbook into a standard Ansible role, added `ansible.cfg`, `group_vars/`, tags, and a thin `site.yml`.
- Re-validated the role: check run, real run, repeat run. Recorded ADR 0009.

## What I learned (in my own words)
Two things about volumes that I would not have got from reading. Mounting a volume over a directory *hides* what the image had there rather than deleting it, which presents as data loss and is not. And a mistyped volume name silently creates a new empty volume instead of failing — so a typo produces a plausible wrong answer rather than an obvious error. That cost me a few minutes of thinking persistence was broken when it was working correctly on a volume I was not looking at.

On roles: the structure *is* the configuration. Ansible finds `templates/motd.j2` because of where it sits, not because a path is written anywhere. Learning the convention is what removes the need to configure anything.

The lesson I actually want to keep is about the refactor, not about Ansible. The rewrite was cleaner than the flat playbook and quietly dropped two fixes the messy version had already earned — the check-mode workaround and the change-reporting suppression. Both were problems I had diagnosed correctly weeks earlier. A refactor discards accumulated fixes as easily as it discards mess, and I did not think to check what I was throwing away.

## Friction / blockers
Two of my own scripts had bugs on first run: a fragile parse of `virsh net-info` that misread an active network as inactive, and a stale `ansible.cfg` setting removed in a newer release. Both were found by reading the actual error text, which named its own fix in the second case.

The Debian package failure looked like a regression and was one — the same check-mode problem as before, reintroduced by the rewrite.
