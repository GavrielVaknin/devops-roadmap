## What I learned (in my own words)
_(Worth revisiting once rested — first attempt below, not final.)_

An SSH key pair is two files: a private key that stays on my machine and never leaves it, and a public key that I hand out to services (GitHub, the Pi) so they can recognize me. `ssh-agent` is a background helper that holds my unlocked private key in memory for the current terminal session, so I don't have to unlock it manually every single time I connect somewhere. `eval "$(ssh-agent -s)"` starts that helper and wires my current terminal up to it in one step.

I ended up with two separate keys — one for the Pi, one for GitHub — rather than reusing one everywhere, on purpose: if one ever gets compromised, only that one connection is exposed, not everything.

## Friction / blockers
Permission denied on the first push attempt — took a bit to realize it was because GitHub had never seen my key before, not because anything was broken. The `eval`/`ssh-agent` concept itself was also confusing at first — had to have it explained a couple of times before it actually clicked that it's just loading a key into memory, nothing more exotic than that.
