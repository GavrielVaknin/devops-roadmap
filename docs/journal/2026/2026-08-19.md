## What I learned (in my own words)
The recovery procedure and the normal procedure turned out to be the same command. There is no separate repair mode to maintain, because reapplying the desired state *is* the repair. That only works because the tool is declarative — a script of steps would have needed its own undo path.

Recovery was also targeted rather than blunt: only the host that had actually drifted changed. The playbook is not a reset button.

For containers, the thing that made everything else make sense: the image is immutable and the container gets a thin writable layer on top. Restarting keeps that layer, destroying discards it. Once that clicked, I could predict the outcome of each test before running it, which felt like the real check on whether I understood it.

## Friction / blockers
The genuinely uncomfortable moment was nearly running `apt remove` against my own ThinkPad instead of the VM, after an SSH session had exited without me noticing. Caught it before it executed. It is recorded in the failure-test evidence rather than quietly left out, because it is exactly the risk ADR 0004's methodology exists to contain, and it turned out to be a real risk rather than a theoretical one.
