Build and confirm a working disposable test VM, per ADR 0004's test-before-apply methodology, before writing any real Ansible playbooks against the Pi 5 or ThinkPad.

## What I did

## What I learned (in my own words)
_(First attempt — worth revisiting once rested.)_

A cloud image is a minimal, pre-built OS disk with no installer step — instead, a program called cloud-init runs automatically on first boot and configures the machine from a small config file. Since I'm not on a real cloud provider, `cloud-localds` fakes that mechanism locally by packaging my config into a small ISO the VM reads at boot, as if it were the cloud's normal metadata service.

The actual virtualization stack is layered: KVM is a kernel feature giving hardware-accelerated access to the CPU's virtualization instructions; QEMU is the program that emulates the actual virtual machine and uses KVM to run it fast; libvirt is a management layer on top of QEMU so VMs can be created/tracked/controlled instead of run as raw one-off processes; `virt-install`/`virsh` are the commands that talk to libvirt.

I also learned that YAML files sometimes contain values written in a completely different syntax nested inside them — like the sudoers-format string inside my `user-data.yaml` — which was confusing until I realized YAML was just treating it as a plain string, not trying to interpret it.
